# ux.md — Article & Vocabulary Tracker (dev-queue)

> 목업 5종(`mockup/login.png`, `list.png`, `note.png`, `form.png`, `words-popup.png`)을 기준으로 화면과 흐름을 정리했다. 회원가입 화면 목업은 없으므로 로그인 화면 톤을 그대로 따르는 것을 기본값으로 제안한다.

## 1. 정보 구조 (IA)

```
/login                (비로그인 진입점)
/signup               (회원가입)
/articles              (리스트, 카테고리 필터 = 쿼리 파라미터)
/articles/new           (새 링크 등록 폼)
/articles/{id}          (상세: 메모 + 단어 관리)
(로그인 직후 1회) 단어 암기 팝업  — 별도 라우트가 아니라 리스트 화면 위 오버레이/프래그먼트
```

## 2. 화면별 상세

### 2.1 로그인 (`login.png`)
- 구성: 서비스명 "DevQueue" + 슬로건("개발 문서, 놓치지 말고 쌓아두기"), 아이디 입력, 비밀번호 입력, 로그인 버튼(검정, full-width), 하단에 "계정이 없으신가요? 회원가입" 링크
- 상태:
  - 기본: 빈 폼
  - 에러: 아이디 없음/비밀번호 불일치 → 폼 상단 또는 필드 하단에 에러 메시지, 입력값은 아이디만 유지(비밀번호는 비움)
- 접근성: 각 입력 필드에 `<label>` 연결, 버튼은 실제 `<button type=submit>`

### 2.2 회원가입 (목업 없음 — 로그인 화면 톤 유지)
- 구성 제안: "DevQueue" 헤더 + 아이디, 닉네임, 비밀번호, 비밀번호 확인 입력 필드, 회원가입 버튼, 하단에 "이미 계정이 있으신가요? 로그인" 링크
- 상태:
  - 아이디 중복 → 에러 메시지, 입력값 유지(비밀번호 제외)
  - 비밀번호/비밀번호 확인 불일치 → 필드별 에러
  - 성공 → 로그인 화면으로 이동 (자동 로그인 여부는 구현 단계 결정, 기본은 "가입 후 로그인 화면으로 이동 + 안내 메시지" 권장 — 세션 처리를 단순하게 유지)

### 2.3 리스트 — "내 문서함" (`list.png`)
- 구성: 페이지 제목 "내 문서함" + 우측 상단 "+ 새 링크" 버튼, 카테고리 탭(전체/개발문서/AI/채용정보, "기타"는 목업엔 안 보이지만 요구사항엔 있으므로 탭에 포함), 아티클 카드 리스트
- 카드 구성: 카테고리 뱃지, 제목(읽음 상태면 취소선), 하단에 "단어 N개 저장됨 · 도메인" 또는 "읽음 · 도메인"
- 상태:
  - 빈 리스트(해당 카테고리에 글 없음): "아직 등록한 링크가 없어요" 류의 빈 상태 메시지 + "새 링크 추가" 유도
  - "전체" 탭은 카테고리 파라미터 없이 전체 조회 (RESEARCH.md §Stage3 주의사항: 빈 문자열로 enum 변환 시도하면 400 에러 나므로 파라미터 자체를 생략해야 함)
  - 활성 탭 강조 표시 (`th:classappend`)
- 인터랙션: 카드를 클릭하면 상세로 이동, "+ 새 링크" 클릭 시 등록 폼으로 이동

### 2.4 상세 — 메모 + 단어 관리 (`note.png`)
- 구성: 카테고리 뱃지 + 우측 "..." 메뉴(수정/삭제/읽음 토글 등 액션 모음으로 추정), 제목, URL(링크), 구분선, "메모" 섹션(텍스트, 인라인 편집 또는 별도 편집 모드), "모르는 단어" 섹션 + 우측 "+ 단어 추가" 버튼, 단어 리스트(단어 · 뜻 · 상태)
- 단어 항목 상태: "암기중"(텍스트 라벨) / 암기완료(체크 아이콘) — 클릭 시 토글로 추정
- 상태:
  - 단어 없음: "등록된 단어가 없어요" 빈 상태
  - 메모 없음: placeholder("메모를 남겨보세요") 표시
- 인터랙션:
  - "+ 단어 추가" → 인라인 입력 행 추가 또는 소형 폼(단어/뜻 입력 후 저장) — 별도 페이지 이동 없이 상세 화면 내에서 처리하는 것을 권장 (모달까지 갈 필요 없음, 폼 POST + 리다이렉트로 충분)
  - 단어 상태 클릭 → 암기여부 토글 (POST + 리다이렉트)
  - 메모 수정 → 별도 저장 버튼으로 POST (자동저장은 범위 밖)

### 2.5 새 링크 등록 (`form.png`)
- 구성: 상단 "← 새 링크 추가" 헤더(뒤로가기), 제목 입력, URL 입력, 카테고리 선택(라디오/토글 버튼 형태, 목업상 "개발문서"가 선택된 상태로 강조 표시됨), 메모(선택, textarea, placeholder "간단한 메모를 남겨보세요"), 하단 "취소"/"저장" 버튼
- 상태:
  - 유효성 에러(제목/URL 누락, 카테고리 미선택) → 필드별 에러 메시지, 입력값 유지
- 인터랙션: "취소" → 리스트로 이동(저장 안 함), "저장" → POST 후 리스트로 리다이렉트

### 2.6 단어 암기 팝업 (`words-popup.png`)
- 트리거: 로그인 성공 직후, 안 외운 단어가 1개 이상 있을 때만 노출 (리스트 화면 위 오버레이)
- 구성: "오늘의 단어 N개"(N ≤ 3), 헤더 "아직 못 외운 단어예요", 단어 카드 목록(단어 + 뜻 + 체크박스), 하단 "확인, 오늘도 시작!" 버튼
- 기본 체크 상태: 목업상 모든 항목이 체크된 것처럼 보임 — **기본값을 전부 체크로 할지 전부 비체크로 할지는 구현 단계 결정 사항**으로 명시 (RESEARCH.md 미결 사항과 별개로 UX 결정). 안전한 기본값은 "전부 비체크"로 시작해 사용자가 실제로 외운 것만 명시적으로 체크하게 하는 것 — 다만 목업 톤을 따르고 싶다면 전부 체크로 시작해도 무방.
- 상태:
  - 안 외운 단어가 3개 미만: 있는 만큼만 카드 표시 (2개, 1개도 정상)
  - 안 외운 단어가 0개: 팝업 자체를 띄우지 않음 (US-13 AC)
- 인터랙션: "확인, 오늘도 시작!" 클릭 → 체크된 단어 id들만 POST → 암기완료 처리 → 팝업 닫힘 → 리스트 화면 노출, 새로고침해도 재노출 안 됨(세션 1회성 플래그)
- 체크박스 관련 주의(RESEARCH.md §7-5): 체크 안 한 항목은 폼 전송 시 파라미터 자체가 안 옴 → 서버에서 `@RequestParam(required=false) List<Long>`로 받고 null이면 빈 리스트로 처리

## 3. 핵심 사용자 흐름 (Flow)

### Flow A — 최초 가입 & 첫 사용
로그인 화면 → "회원가입" 클릭 → 회원가입 폼 작성/제출 → 로그인 화면 → 로그인 → (단어 0개이므로 팝업 없음) → 빈 리스트("아직 등록한 링크가 없어요") → "+ 새 링크" → 등록 폼 작성/제출 → 리스트에 반영

### Flow B — 일상적 재방문 (핵심 시나리오)
로그인 → 안 외운 단어 있으면 팝업 노출 → 아는 단어 체크 → "확인, 오늘도 시작!" → 리스트 화면 → 카테고리 탭으로 필터링 → 카드 클릭 → 상세에서 메모 확인/수정, 새 단어 추가

### Flow C — 비로그인 접근 차단
비로그인 상태에서 `/articles` 등 임의 URL 직접 접근 → 인터셉터가 감지 → `/login`으로 리다이렉트 (로그인 후 원래 요청 페이지로 되돌리는 기능은 범위 밖, 단순히 리스트로 보내는 것으로 충분)

## 4. 에러 & 엣지 케이스 정리

| 상황 | 처리 |
|---|---|
| 아이디 중복 가입 | 회원가입 폼에 에러 메시지, 입력값(아이디 제외 또는 전체) 유지 |
| 로그인 실패 | 로그인 폼에 공통 에러 메시지("아이디 또는 비밀번호가 올바르지 않습니다") — 아이디 존재 여부를 노출하지 않기 위해 구체적 원인 구분 안 함 |
| "전체" 카테고리 필터 | `category` 파라미터 생략 (빈 문자열 전달 금지) |
| 안 외운 단어 0개 | 팝업 미노출 |
| 안 외운 단어 <3개 | 있는 만큼만 노출 |
| 팝업에서 아무것도 체크 안 함 | 전부 미체크 상태로 정상 제출 가능, 암기완료 처리 0건 |
| 타 사용자 아티클 URL 직접 접근 (`/articles/{다른유저의id}`) | 404 또는 403 처리 (US-6 연장) — 구현 단계에서 소유자 검증 로직 필수 |
| 메모/단어 없는 상세 화면 | 빈 상태 placeholder 텍스트 표시 |

## 5. 범위 밖 UX

- 로딩 스피너, 스켈레톤 UI (서버 렌더링 + 단순 폼 흐름이므로 불필요)
- 다크모드, 반응형 브레이크포인트 세밀 대응
- 토스트/스낵바 같은 정교한 알림 컴포넌트 — Thymeleaf 플래시 메시지(리다이렉트 후 1회성 메시지) 수준으로 충분
