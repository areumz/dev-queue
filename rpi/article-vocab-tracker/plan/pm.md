# pm.md — Article & Vocabulary Tracker (dev-queue)

> 이 프로젝트는 **Spring Boot 학습을 위한 개인 프로젝트**입니다. 따라서 이 문서의 "요구사항"과 "성공 기준"은 비즈니스 성과가 아니라 **학습 목표 달성 여부**를 기준으로 작성했습니다.

## 1. 배경 & 목적

- Java/Spring Boot를 처음 배우고 있으며, 실습용으로 평소 보는 개발 아티클/영상을 저장하고 모르는 단어를 복습하는 개인 도구를 직접 만들고자 함.
- 목적은 "완성도 높은 제품"이 아니라, **DI, MVC, Thymeleaf, 세션 인증, 연관 엔티티, 데이터 계층 교체(메모리→JPA)** 라는 핵심 개념을 손으로 직접 구현하며 익히는 것.

## 2. 사용자 & 페르소나

- 여러 개발 아티클/영상을 즐겨찾기처럼 쌓아두는데, 읽을 때 문서가 흩어지거나 찾기 어려웠던 문제를 겪고 있음
- 아티클을 읽으며 모르는 영단어를 만나면 그때그때 적어두고 외우고 싶음
- 매일 가볍게 단어 3개씩 복습하고 싶음

여러 사용자가 가입할 수 있는 구조(User 엔티티, 세션 인증)이고, "다른 사용자와 데이터가 섞이지 않는다"를 검증하는 정도의 멀티유저 개념 학습이 목적이다.

## 3. 기능 요구사항 (User Stories)

### 인증
- **US-1**: 사용자로서, 아이디/비밀번호/닉네임으로 회원가입할 수 있다.
  - AC: 비밀번호는 평문으로 저장되지 않고 BCrypt로 해시되어 저장된다.
  - AC: 아이디 중복 가입 시도 시 에러 메시지와 함께 회원가입 폼으로 되돌아간다.
- **US-2**: 사용자로서, 아이디/비밀번호로 로그인할 수 있다.
  - AC: 로그인 성공 시 세션이 생성되고 리스트 화면으로 이동한다.
  - AC: 로그인 실패(존재하지 않는 아이디/틀린 비밀번호) 시 에러 메시지가 표시된다.
- **US-3**: 사용자로서, 로그아웃하면 세션이 종료되고 다시 로그인 화면으로 이동한다.
- **US-4**: 비로그인 사용자로서, 로그인/회원가입 페이지를 제외한 모든 페이지에 접근하면 로그인 화면으로 리다이렉트된다.

### 아티클 관리
- **US-5**: 로그인한 사용자로서, 제목/URL/카테고리/메모를 입력해 새 아티클(링크)을 등록할 수 있다.
  - AC: 카테고리는 개발문서/AI/채용정보/기타 중 하나를 반드시 선택한다.
  - AC: 등록 후 리스트 화면으로 리다이렉트되고 방금 등록한 항목이 보인다.
- **US-6**: 로그인한 사용자로서, 내가 등록한 아티클만 리스트에서 볼 수 있다 (다른 사용자 것은 보이지 않는다).
- **US-7**: 로그인한 사용자로서, 카테고리 탭으로 리스트를 필터링할 수 있다 (전체/개발문서/AI/채용정보/기타).
- **US-8**: 로그인한 사용자로서, 아티클 상세 화면에서 메모를 수정할 수 있다.
- **US-9**: 로그인한 사용자로서, 아티클의 읽음 여부를 토글할 수 있다.
  - 참고: 자동 처리 vs 수동 토글 여부는 RESEARCH.md 미결 사항(§3-3) — 구현 단계에서 직접 결정.

### 단어(Vocabulary) 관리
- **US-10**: 로그인한 사용자로서, 아티클 상세 화면에서 모르는 단어와 뜻을 등록할 수 있다.
- **US-11**: 로그인한 사용자로서, 등록한 단어의 암기 여부를 토글할 수 있다.
- **US-12**: 로그인한 사용자로서, 등록한 단어를 삭제할 수 있다.

### 단어 암기 팝업
- **US-13**: 로그인 직후, 내가 소유한 아티클들에 속한 단어 중 암기여부=false인 단어 중 최대 3개가 랜덤으로 팝업에 노출된다.
  - AC: 안 외운 단어가 3개 미만이면 있는 만큼만 보여준다.
  - AC: 안 외운 단어가 0개면 팝업이 뜨지 않거나 빈 상태 메시지를 보여준다 (구현 단계에서 택1).
- **US-14**: 사용자로서, 팝업에서 체크한 단어만 암기완료(암기여부=true)로 처리하고 나머지는 그대로 둔다.
- **US-15**: 사용자로서, 같은 로그인 세션 내에서 새로고침해도 팝업이 다시 뜨지 않는다 (1회성).

## 4. Out of Scope (이번 프로젝트에서 제외)

RESEARCH.md §8 범위 조정 제안을 그대로 반영:
- Spring Security 도입 (직접 만든 세션 인증으로 충분, Security는 다음 프로젝트로 이연)
- 고급 유효성 검사 (커스텀 Validator 등) — `@Valid`+기본 제약 애너테이션 수준까지만
- 페이지네이션 / 검색 / 태그 기능
- 계층별 DTO 분리 (회원가입의 비밀번호 확인처럼 명확히 필요한 경우 제외하고 도메인 객체를 뷰에 직접 전달)
- 반응형/고급 스타일링 (목업 재현은 선택 사항, 학습 흐름을 막지 않도록 최우선순위 아님)
- 다른 사용자의 게시물 공유/열람 기능 (기본적으로 본인 것만 접근 가능)

## 5. 성공 기준 (학습 프로젝트 관점)

전통적인 "비즈니스 성공 지표" 대신, 아래 기준으로 완료 여부를 판단한다:

1. RESEARCH.md Stage 0~7의 각 완료 기준을 스스로 통과했다 (눈에 보이는 동작 확인).
2. Stage 1에서 설계한 Repository 인터페이스가 Stage 8(JPA 전환)에서 **Controller/Service 코드 변경 없이** 구현체만 교체 가능했다 — 이것이 이 프로젝트의 핵심 학습 성과 지표.
3. 인증되지 않은 사용자가 다른 사람의 데이터에 접근할 수 없음을 직접 확인했다 (2개 계정으로 교차 검증).
4. §7(RESEARCH.md)에 정리된 초보자 함정들을 실제로 겪거나, 미리 인지하고 피했다.
