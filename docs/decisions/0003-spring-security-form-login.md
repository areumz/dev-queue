# 0003. 로그인을 Spring Security 폼 로그인으로 교체

- 상태: 확정 (2026-11-15)
- 사이클: v2-0b

## 맥락

직접 만든 로그인은 CSRF 방어가 없었다. CSRF는 로그인한 사용자의 브라우저를 속여, 다른 사이트에서 우리 서버로 요청을 몰래 보내게 하는 공격이다. 세션에는 `User` 엔티티를 통째로 넣고 있었고, 로그인 뒤에 세션 ID도 바꾸지 않았다.

## 선택지

- **직접 CSRF 토큰 구현**: 의존성이 늘지 않는다. 보안 코드를 직접 유지해야 하고 실수하기 쉽다.
- **Spring Security 폼 로그인**: CSRF 토큰, 로그인 때 세션 ID 재발급, 접근 규칙을 기본으로 준다. 설정을 배워야 한다.

## 결정

v2-0b에서 Spring Security 폼 로그인을 도입한다. 세션에는 `User` 대신 id, 아이디, 닉네임만 가진 `LoginUser`를 담는다.

## 이유

- 직접 만든 CSRF는 v2-0c에서 어차피 버리게 된다. v2-0c의 OAuth2 로그인(구글 같은 외부 계정으로 로그인)이 같은 Security 필터 체인에 붙는다.
- 인증과 CSRF처럼 틀리기 쉬운 부분은 검증된 라이브러리에 맡긴다.

## 결과

- 배포 직후 기존 세션이 무효가 되어 모든 사용자가 한 번 다시 로그인해야 한다. 비밀번호는 그대로 쓴다.
- 모든 폼은 `th:action`을 써야 CSRF 토큰이 들어간다. 세션이 만료된 뒤 폼을 제출하면 403 화면이 나온다.
- 테스트의 POST 요청에는 `.with(csrf())`가 필요하다.
