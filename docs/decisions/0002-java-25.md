# 0002. Java 17에서 25로 전환

- 상태: 확정 (2026-11-10)
- 사이클: v2-0a

## 맥락

v1은 강의 실습 기준인 Java 17로 만들었다. 개발 Mac에는 Java 26만 있어서 빌드가 되지 않았다. 어차피 toolchain 설정을 손봐야 했다.

## 선택지

- 17 유지: 변경 없음. 두 단계 전 LTS.
- 21: 한 단계 위 LTS.
- 25: 최신 LTS(2025년 9월). 다음 LTS는 29(2027년 9월 예정).

## 결정

Java 25. JDK는 foojay 플러그인으로 Gradle이 자동으로 받는다.

## 이유

- 최신 LTS라 지원 기간이 가장 길다.
- 가상 스레드를 쓸 수 있다. v2-1 이후 LLM·크롤링처럼 외부 API를 기다리는 작업에 맞다.
- Spring Boot 4가 공식 지원한다.
- foojay로 JDK를 받으면 개발자 컴퓨터, CI, 서브에이전트 어디서든 따로 설치하지 않고 같은 버전으로 빌드된다.

## 결과

- SpotBugs Gradle 플러그인을 6.0.7 → 6.5.13으로 올렸다. 6.0.7은 Java 25 바이트코드를 분석하지 못한다.
- IntelliJ 실행 버튼이 Gradle을 거치지 않게 설정돼 있으면 IntelliJ에서 JDK 25를 받아야 한다(Project Structure → SDK → Download JDK).
- 배포 서버(EC2)의 Java도 25로 맞춰야 한다. 다음 배포 전에 확인한다.
