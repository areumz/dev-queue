# v2-0 기반 작업 개요

v2 기능(API 분리, 확장 프로그램, 추천)을 올리기 전에 바닥을 다지는 단계다.
한 사이클로는 너무 커서 4개로 나눴다. 각 사이클은 브레인스토밍 → 설계 승인 → 계획 → 구현 → 머지를 따로 돈다.

| 순서 | 사이클 | 목표 | 상태 |
|---|---|---|---|
| a | [테스트 기반](a-test-foundation-brainstorming.md) | 외부 DB 없이 테스트가 돌고, CI가 실패한 PR을 막는다 | 구현 완료, PR 리뷰 대기 |
| b | 버그·보안 수정 + 최소 Spring Security | 브리프 1장 수정. IDOR 재현 테스트가 첫 작업 | 대기 |
| c | 로그인 고도화 | 마이페이지, 비밀번호 찾기(메일), SNS 로그인 | 대기 |
| d | `user_event` 로그 | 추천·평가에 쓸 행동 기록을 쌓기 시작 | 대기 |

## 순서를 이렇게 정한 이유

- **a가 맨 앞**: superpowers는 TDD가 전제다. 테스트를 돌릴 수 없으면 b부터 막힌다.
- **최소 Spring Security를 b에 넣음**: CSRF 방어를 직접 만들면 c에서 Security를 넣을 때 전부 버린다. c까지 미루면 그동안 보안 구멍이 열려 있다. 그래서 로그인 체크, CSRF, 세션 ID 재발급만 b로 당기고, 마이페이지·비밀번호 찾기·SNS 로그인은 c에 남긴다.
- **IDOR 재현 테스트를 a가 아닌 b에 둠**: 버그를 재현하는 테스트는 고치기 전까지 실패한다. a에 넣으면 a의 PR이 CI에 막히거나, main에 빨간 테스트가 남는다. b에서 "실패 확인 → 수정 → 통과"를 한 PR 안에서 끝낸다.

## 사이클 사이에 넘기는 것

- a → b: 통합 테스트 틀(`@IntegrationTest`), 로그인 흉내 도우미, 테스트를 돌리는 CI
- b → c: Spring Security 설정 뼈대. b에서 로그인 흉내 도우미를 Security 방식으로 교체한다.

## 브리프에서 바뀐 점

- 브리프 3장 "v2-0 기반"의 1~4번을 a~d 사이클로 나눴다.
- 브리프 5-2장 완료 기준 "IDOR 재현 테스트가 존재한다"는 b로 옮겼다(위 이유).
- Java 17 → 25로 올린다(a에서 처리).
