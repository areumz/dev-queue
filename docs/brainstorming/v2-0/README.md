# v2-0 기반 작업 개요

v2 기능(API 분리, 확장 프로그램, 추천)을 올리기 전에 바닥을 다지는 단계다.
한 사이클로는 너무 커서 4개로 나눴다. 각 사이클은 브레인스토밍 → 설계 승인 → 계획 → 구현 → 머지를 따로 돈다.

| 순서 | 사이클 | 목표 | 상태 |
|---|---|---|---|
| a | [테스트 기반](a-test-foundation-brainstorming.md) | 외부 DB 없이 테스트가 돌고, CI가 실패한 PR을 막는다 | 완료 (PR #15) |
| b | [버그·보안 수정 + 최소 Spring Security](b-security-fixes-brainstorming.md) | 브리프 1장 수정. IDOR 재현 테스트가 첫 작업 | 구현 완료, PR 2 리뷰 대기 |
| c-1 | [마이페이지](c1-mypage-brainstorming.md) | 정보 수정, 비밀번호 변경, 탈퇴, 이메일 칸 추가. 닉네임을 바꾸면 세션의 `LoginUser`도 같이 갱신 | 구현 완료, PR 리뷰 대기 |
| c-2 | 비밀번호 찾기 | 메일 발송, 만료되는 1회용 토큰, 이메일 소유 확인 | 대기 |
| c-3 | SNS 로그인 | OAuth2 Client. 시작 전에 할 가치가 있는지 다시 판단 | 대기 |
| d | `user_event` 로그 | 추천·평가에 쓸 행동 기록을 쌓기 시작. 운영 설정 정리(`ddl-auto`, Flyway), `username` 유니크 제약(동시 가입 중복 방지)도 여기서 | 대기 |

## 순서를 이렇게 정한 이유

- **a가 맨 앞**: superpowers는 TDD가 전제다. 테스트를 돌릴 수 없으면 b부터 막힌다.
- **최소 Spring Security를 b에 넣음**: CSRF 방어를 직접 만들면 c에서 Security를 넣을 때 전부 버린다. c까지 미루면 그동안 보안 구멍이 열려 있다. 그래서 로그인 체크, CSRF, 세션 ID 재발급만 b로 당기고, 마이페이지·비밀번호 찾기·SNS 로그인은 c에 남긴다.
- **IDOR 재현 테스트를 a가 아닌 b에 둠**: 버그를 재현하는 테스트는 고치기 전까지 실패한다. a에 넣으면 a의 PR이 CI에 막히거나, main에 빨간 테스트가 남는다. b에서 "실패 확인 → 수정 → 통과"를 한 PR 안에서 끝낸다.

## 사이클 사이에 넘기는 것

- a → b: 통합 테스트 틀(`@IntegrationTest`), 로그인 흉내 도우미, 테스트를 돌리는 CI
- b → c: Spring Security 설정 뼈대. b에서 로그인 흉내 도우미를 Security 방식으로 교체한다.
- c-1 → c-2: `User.email` 칸(인증 없이 저장됨, 중복 불가). c-2에서 **이메일 소유 확인(인증 메일)**을 붙인 뒤에야 비밀번호 찾기에 연결한다.
- c-1 → c-3 이후: 비밀번호 변경·탈퇴 때 **다른 기기의 세션이 유지되는 한계**. 모든 세션을 끊는 방식(`SessionRegistry` 또는 DB 세션)은 로그인 방식이 늘어나는 c-3 또는 d 이후에 다시 판단한다. (탈퇴 후 남은 세션으로 주인 없는 글이 생길 수 있다.)
- c → d: `email`·`username` DB 유니크 제약(앱 코드 검사만 있어 동시 요청에 약함). `GET /articles`가 팝업을 소진하는 문제의 정책 결정. 글을 지우는 다른 경로가 생기면 DB 외래 키(`ON DELETE CASCADE`)로 단어·글을 지우도록 테이블 변경.

## 브리프에서 바뀐 점

- 브리프 3장 "v2-0 기반"의 1~4번을 a~d 사이클로 나눴다.
- 브리프 5-2장 완료 기준 "IDOR 재현 테스트가 존재한다"는 b로 옮겼다(위 이유).
- Java 17 → 25로 올린다(a에서 처리).
